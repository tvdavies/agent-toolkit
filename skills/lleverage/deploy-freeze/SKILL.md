# Deploy freeze

Pausing and resuming deploys are production actions. Do them only when Tom asks
or a freeze has been requested in Slack and Tom has asked you to handle it.

## How deploys flow

Merge to `main` → Cloud Build builds the image → `tooling/scripts/update-infra-repo.sh`
bumps the overlay in `lleverage-ai/infrastructure` → Argo CD auto-syncs the change.

The freeze works at the Argo CD level, not Cloud Build:

- CI keeps building and bumping the infra repo during the freeze. On resume
  Argo syncs every app to the latest infra commit, so nothing merged during the
  freeze is lost. Disabling Cloud Build triggers would drop those builds and
  need manual re-runs per service.
- It also stops infra-repo changes from rolling out.
- Prod Applications are generated by ApplicationSets
  (`internal-services-production`, `organisations-production`,
  `platform-production`, `serverless-consumers-production`), which revert
  direct edits to an Application. The script removes `automated` from the
  ApplicationSet templates instead, saving the old policy in an annotation.
  The ApplicationSets are applied by hand with kubectl, so the patch sticks
  until someone re-applies them.
- About 20 Helm child apps (loki, longhorn and so on) keep auto-sync, but their
  specs come from frozen parent apps, so they can't pick up changes.

Not covered: `logging-service` deploys go through Terraform to Cloud Run, not Argo.

## Commands

`scripts/deploy-freeze.sh` (all take `--env production|staging`, default production):

```bash
deploy-freeze.sh status
deploy-freeze.sh pause --until 14:30 --reason "Demo for <who>"   # local time; or "YYYY-MM-DD HH:MM"
deploy-freeze.sh resume                                           # also cancels the scheduled resume
deploy-freeze.sh sync production-<service>                        # one-off sync for an urgent fix
```

`--until` creates a transient systemd user timer `deploy-freeze-resume-<env>`
on this machine (linger is enabled, so it runs without a login session). It does
not survive a reboot or machine shutdown. Logs:
`journalctl --user -u deploy-freeze-resume-production`.

## Procedure

1. Confirm the window and the timezone. People say "CET" when they mean local
   Amsterdam time, which is CEST in summer. Use local time.
2. `pause --until … --reason …`, then check that the output says every
   ApplicationSet-generated app has auto-sync off.
3. Also schedule a session check (CronCreate, a few minutes after the resume)
   to run `status` and report back, in case the machine was off.
4. Reply in the Slack thread when the freeze is on and when it lifts (confirm
   the wording with Tom first).
5. Urgent fix during the freeze: merge as normal, wait for the infra bump
   commit, then `sync production-<service>`.
6. After resume, expect a burst of rollouts for everything merged during the
   freeze. Run the prod-health skill afterwards.
